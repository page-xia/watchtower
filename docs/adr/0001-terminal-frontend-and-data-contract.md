# ADR 0001: 日内终端前端与数据契约

## 状态

已采用（第一版）。

## 背景

盯盘页面需要同时承载全市场板块排序、股票表、日内回放和消息证据。行情刷新频率高，收盘后又必须保持快照稳定；逐笔成交回报应作为重要成交事实输入，但不能把它或盘口代理描述成 委托队列。

## 决策

### ECharts + 原生前端

使用固定版本的本地 `static/vendor/echarts.min.js`（5.6.0）和原生 HTML/CSS/JavaScript。这样图表在生产环境不依赖 CDN，也不需要引入前端构建链；ECharts 负责折线、分时、量柱、十字光标和缩放，业务状态仍由现有 FastAPI 接口驱动。

### 轻量终端 payload

`/api/dashboard?view=terminal` 和终端 WebSocket 返回板块、当前页股票和必要状态字段。后端仍扫描全市场，`total` 明确告知扫描范围，分页只限制浏览器渲染数量。WebSocket 不再重复推送旧版机会卡片和核心票卡片，详情按需通过 `/api/signals/{code}/detail` 加载。

### 收盘缓存与刷新

交易时段行情快照和终端上下文默认约 5 秒缓存，板块资金动能约 20 秒刷新；收盘上下文缓存 300 秒，并以交易时段边界作为缓存隔离。收盘 payload 的时间固定为 `15:00:00`，前端只有 payload 内容变化时才重绘。

### 逐笔成交与大单观察口径

`OrderFlowObservation` 由 easy_tdx 五档委买委卖深度、`b_vol/s_vol` 汇总主动成交量和分钟成交额加速计算，字段中保留数据源、时间、深度差、方向、触发证据和 `confidence` 可信度说明。标准 easy_tdx A 股协议不提供委托队列或逐笔委托，因此默认质量固定为 `L1_five_level`；只有外部适配器明确返回扩展字段时才允许标记 委托队列。easy_tdx 收盘数据、历史回放和缺少五档时统一返回不可用，不生成虚假的 委托队列 结论。

个股详情可以按需调用 easy_tdx 的 `get_transaction_data` 或
`get_history_transaction_data`，生成独立的 `TransactionFlowObservation`。
接口选择必须先判断当前时段和请求日期：当前处在 `is_trading_window()` 定义的盘中窗口，且请求日期是当天时，使用 `get_transaction_data`；非盘中、周末、节假日、收盘后或请求历史交易日时，使用 `get_history_transaction_data` 并传入明确交易日。它优先使用返回的 `buyorsell`（`0` 买、`1` 卖），特殊或盘后方向值按中性，字段缺失时才根据相邻成交价计算方向成交额和大额成交差；质量标记为
`l1_transaction`。该摘要是买盘承接、放量抛压、A/B 分级和减 T 辅助判断的重要分析数据；但它不改变“标准 easy_tdx 没有 委托队列”的结论，全市场扫描不批量请求逐笔成交。

### 集合竞价口径

竞价字段分为 `actual` 和 `proxy`。`actual` 只用于 easy_tdx 明确返回集合竞价明细、历史 09:25 竞价快照或历史 09:25 成交回填时；`09:15-09:29` 的价格、`cur_vol` 和五档快照只作为 `proxy`，并保存多快照轨迹以识别指示价上修/下修。竞价只能生成开盘候选，正式买 T 最早在开盘第 3 分钟后，且必须再次满足指数、板块、分时量能和盘口代理共振。收盘页面只显示历史竞价回填，不再使用“可生成开盘候选”的实时文案。

### 拐头状态口径

策略引擎按分钟保存短窗口的指数归一化价格、分钟量能和日内反弹状态。首个快照
只能标记为 `snapshot_rebound_proxy`；至少有连续分钟状态后，才用“先弱/平 ->
当前正斜率 + 量能扩张”标记 `rolling_turn`。这只是把指数拐头逻辑变成可解释状态，
不把单次高低点当作已确认反转。买 T 仍需同时满足板块核心进攻、个股分时放量、
低位拐头以及五档/成交额代理承接；卖 T 继续使用 8-10% 反弹兑现和动能衰减条件。

## 后果

- 页面首屏可以稳定比较板块和板块内股票，详情只在用户点开时取完整回放。
- 数据源受限或收盘时仍能展示可解释的快照，但不会提供伪实时盘口结论。
- ECharts 的本地文件需要随部署包发布；后续若迁移 Vue，接口和数据模型可继续复用。
